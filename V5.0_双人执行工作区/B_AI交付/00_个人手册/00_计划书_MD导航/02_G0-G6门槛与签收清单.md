# G0-G6 门槛与签收清单

## 使用原则

- 门槛必须按顺序通过，不能跳过。
- `G0/G1` 也要留下检查结果和证据；`G2` 因为是 A 向 B 的正式接口交接，所以特别强调 A/B 双方签收。
- 每项只能记录 `PASS`、`FAIL` 或 `BLOCKED`。
- 没有文件、截图、日志、哈希或交叉复核，不得写 `PASS`。

## G0 输入锁定

目标：先确认“用的是哪一套真实输入”，避免对错包、旧包或被修改的文件继续工作。

- [ ] 已确认真正的内层 ZIP，而不是外层同名目录。
- [ ] 已确认 18 张正式工作簿。
- [ ] 已确认 3 张控制工作簿。
- [ ] 原 ZIP、原工作簿保持只读。
- [ ] 已核对输入文件大小和 SHA-256。
- [ ] 已明确 A、B 的对象所有权和证据目录。
- [ ] 已生成输入清单和哈希记录。

判定：路径错误、文件数不符、哈希不符或原文件可被误写时，记录 `FAIL` 或 `BLOCKED`，不得开始正式导入。

## G2 模型冻结与 A/B 签收

目标：A 固定下游接口，B 复核并接收。G2 不是最终项目验收，而是“模型现在可以正式给 B 使用”的交接门槛。

### A 必须完成

- [ ] 18 张正式表和 3 张辅助表全部导入。
- [ ] 正式表总行数为 `313,593`。
- [ ] 主键重复数和空主键数为 `0/0`。
- [ ] 关系中不存在事实表之间的多对多或循环。
- [ ] 建关系前后事实行数不膨胀。
- [ ] 地区桥只保留 region，不向国家传播。
- [ ] 基础指标已定义公式、粒度、单位、日期口径、空值规则、来源表和允许页面。
- [ ] 模型版本、修订号和冻结时间明确。
- [ ] B 权限为可读不可写。

### G2 后的变更规则

- A 不得静默修改字段名、类型、关系或指标。
- 如确需修改，A 发布新修订号并列出受影响的 DB03/DB05/DB06 和 AI 题。
- B 收到通知后暂停受影响对象，复测通过后再恢复。
- G2 未签收前，B 只能继续做线框、知识规则、25问基准、报告框架和视频脚本，不能正式搭页或另建影子模型。
